# 参考分工

图像和视频模型会把参考图里的一切都当成可以迁移的信息。参考图越专一，模型越不容易混淆。

## 可以分配的职责

| 职责 | 典型来源 | 写法示例 |
|---|---|---|
| 身份（长什么样） | 面部锁定图（2×2 四视图） | "图片1是人物面部的四视图，只用来确定长相" |
| 服装 | 服装图、假人穿搭图 | "图片2提供服装" |
| 身材与比例 | 带完整身体的全身图 | "头身比例以图片2为准" |
| 姿势 | 服装图或对标图里的站姿 | "姿势参考图2" |
| 构图与场景 | 对标照片、首帧 | "图片3只提供构图和场景" |
| 动作与节奏 | 参考视频 | "视频1只提供动作、节奏和身体朝向" |

一张图可以承担几项职责，比如假人穿搭图同时提供服装、身材和姿势，这正是穿衣合成效果好的原因之一。但每一项职责只能有一个来源。

## 写明不能迁移的东西

模型会默认"参考里有的都要"。下面这些情况必须在提示词里写明不迁移：

- **参考视频里人物的外貌和服装。** "视频1只提供动作，不提供人物外貌、服装、配饰或场景。即使视频1中的舞者戴着手套，也不能把手套迁移到模特身上。"笼统的排除不够，要逐项列出差异，见 `nuwa-motion` 的 [防外观迁移](../../nuwa-motion/references/anti-transfer.md)。
- **对标照片里另一个人的脸。** 对标照片里的真人模特会和你的身份图抢"这个人长什么样"。能不传就只用文字描述构图；必须传时，先把人物整体涂掉，只留场景。
- **假人的质感。** 服装图是假人时，加"禁止假人、禁止肢体衔接处的人偶线条"，否则关节缝和塑料感会被带到真人身上。
- **多视图被当成多个人。** "图片1是同一个人的四视图，左上正面、右上 45 度、左下侧面、右下背面，是同一个人，不是四个人。"全身三视图同理。
- **无头裁图被当成画面内容。** "图片2中没有头部只是因为裁掉了，人物的头部和脸完全以图片1为准。"

## 景别冲突与大头娃娃

脸部特写和身体图是两种景别。如果身体图里没有头（无头裁图），模型就没有头和身体的比例依据，只能把特写里看到的头直接拼上去，结果就是头偏大。

解法按可靠程度排序：

1. **让一张带完整身体的全身图负责比例。** 穿衣合成时用带头或带假人头部轮廓的全身服装图；视频生成时用合成好的成品全身图。
2. **在提示词里说破景别。** "图片1是面部特写，景别比成片大得多，只用来确定长相，不代表头部在画面里的大小。"
3. **先合成首帧再生视频。** 比例在首帧的像素里就固定了，视频模型只负责让它动起来。

## 复刻时参考图要对上参考视频的视角

用参考视频加图片做视频复刻（换人）时，图片的视角、构图、机位要尽量和参考视频一致。参考视频是正面平视，图片也用正面平视；参考视频从侧前方拍，就挑侧前方的那张。对不上时，模型要一边把人从图片的角度"转"到视频的角度，一边跟随动作，人物就会畸变。Wan 系列有这个问题。

所以三视图能不能用，不在于它是三视图，而在于里面有没有一格和参考视频的视角对得上。对得上的那一格可以裁出来单独用。

## 选模型与成图回喂

**第一次出图选 GPT Image。** 用户丢进来的原始参考图，不管是照片、截图还是 Midjourney 出的图，来源不限，第一次出图（正面基准脸、锁定图、穿衣合成）首选 GPT Image，身份还原度最高。

**尽量少把 GPT Image 的成图再喂给 GPT Image。** 每回喂一次，面部都可能被重绘一次，越改越不像本人。具体规则：

1. **流程衔接可以。** 用户确认过的定稿往下一环传，是正常衔接：基准脸 → 锁定图，锁定图 → 穿衣合成，成品全身图 → 视频。每份定稿只往下传，不回头在它上面改。
2. **不在同一张成图上反复改。** 不满意就回到上一份定稿或原始参考，改提示词重新生成，不在当前成图上一层层叠改。
3. **局部编辑用 Nano Banana Pro。** 换发型、去妆、改小处这类编辑，交给 Nano Banana Pro，不用 GPT Image 做编辑。
4. **每次回喂都要写明。** 生成记录和确认单里，每张输入图都标明来源：用户原始参考，还是哪一次生成的成图、第几次回喂。

用户坚持拿 GPT Image 的成图去改时，先友好地提醒："GPT Image 每改一轮都可能重绘面部，越改越不像本人，建议回到上一份定稿或原始参考重新生成。"用户坚持就照做，并在生成记录里写明风险。

**不要擅自换模型。** 回喂规则和用户的要求冲突、或者发现要提交的图来源不清时，停下来说清是哪几张图、来源是什么、可能丢什么，给两个选项让用户选（回到原始参考和已认可的提示词重出，或换 Nano Banana Pro 做局部编辑）。用户没回话不等于同意换通道。

**提交前逐张自检**，结果写进生成记录，下一次会话只能靠记录判断来源：

```text
每张输入图：
  来源写得出来吗（用户原始参考 / 哪次生成的定稿）？   写不出 → 先查记录，查不到就停下来问
  是 GPT Image 成图吗？是第几次回喂？                超过一次 → 提醒用户，改用定稿或原始参考
  无头裁图：头部完全裁掉、没混进旁边分区？           否 → 重裁
  顺序和职责写清了吗？                               否 → 补
```

其他模型也有同样的退化：拿同一个模型的成图反复改，皮肤会先变成均匀色块，骨相再向模型的"平均脸"收敛。原则一样：改图回到上一份定稿或原始参考。
