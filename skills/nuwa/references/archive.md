# 制作档案

一个模特一份档案。档案是下一次会话唯一可靠的记忆：对话会被压缩、会被删除，文件不会。

## 默认结构

项目有自己的目录约定时以项目为准。没有时用下面这套：

```text
<项目>/模特/<模特名>/
├── 需求边界.md          用途、气质、禁区（nuwa-casting 第 1 步）
├── 参考证据.md          参考图评审：逐张打分、职责、角度覆盖
├── 设计方案.md          多人融合时的识别锚点（可选）
├── 角色锁定.md          选角定脸的结论（nuwa-casting）     ┐
├── 身材卡.md            头身比、体型、比例来源图（nuwa-body）├ 角色包
├── 衣橱.md              所有造型条目（nuwa-wardrobe）       ┘
├── 场景/
│   └── <场景名>.md      场景卡与对标图（nuwa-studio 的选景）
├── 素材/
│   ├── 外部参考/         用户提供的原始参考，保持原样不覆盖
│   ├── 定稿/             用户认可、要继续使用的图
│   └── 过程/             生成过程中的候选和废稿
└── 生成记录/
    └── <日期>-<任务名>/  每次提交一个目录（见下）
```

## 每次生成的记录目录

```text
生成记录/YYYY-MM-DD-棚拍花絮-720P/
├── 确认单.html          生成前确认的确认单（用户确认原话记在生成记录里）
├── prompt.txt            提交的提示词原文，一字不改
├── request.json          模型、通道、参数、参考图清单及各自职责
├── submission-started.json   提交前写入，防止网络中断后重复提交
├── receipt.json          接口回执（任务 ID、状态、用量）
├── <成片或成图>
└── 检查记录.md           抽帧检查结论、问题项、用户评价
```

`request.json` 至少要有这些字段，接口没回传的写"待核实"，不要猜：

| 字段 | 内容 |
|---|---|
| 模型与通道 | 实际模型标识、走的是 API、反代还是网页版 |
| 参数 | 尺寸、张数、时长、质量档位等实际提交值 |
| 参考图 | 每张的路径、职责、来源；生成图要写明是第几次回喂 |
| 输出像素 | 读文件得到的实际像素，不写请求里的目标尺寸 |
| 执行环境 | 当时会话用的主模型和推理强度，取不到写"未记录" |
| 文件指纹 | 输出文件的 SHA256，归档移动后用来核对 |

认可过的提示词复用时从 `prompt.txt` 复制，不要凭记忆重打。重抽之前先比对当时的执行环境和这次是否一致，不一致先告诉用户。

`submission-started.json` 要在发出请求之前写好。请求结果不明时，先用任务 ID 查询，不要直接重新提交，否则可能重复扣费。

## 档案各文件只装各自的东西

| 文件 | 回答的问题 | 不要放进来 |
|---|---|---|
| 需求边界 | 这个模特给谁看、要什么、不要什么 | 具体长相 |
| 参考证据 | 每张参考图能用来定什么、不能用来定什么 | 生成结果 |
| 角色锁定 | 这个人以后长什么样 | 一次次的生成参数 |
| 身材卡 | 身体比例以哪张图为准、是多少 | 服装 |
| 衣橱 | 有哪几套造型、每套的服装描述和定稿图 | 场景、动作 |
| 场景卡 | 在哪拍、怎么拍 | 人物 |
| 生成记录 | 这一次具体提交了什么、得到了什么 | 长期结论 |

长期有效的结论从生成记录里提炼出来，写回上面几份文件。生成记录本身只增不改。

## 新会话怎么接着做

先读角色锁定、身材卡和衣橱，确认这个模特现在是什么样子；再看最近一次生成记录，确认上次做到哪一步、用户怎么评价。三样里缺哪样，就先补哪样，不要凭对话里的印象继续生成。
