# 模型能力速查表

每个模型都有自己擅长和不擅长的事。写提示词前先在这里选模型，再按它的长处和短处写。这张表会随新模型出现而更新；和眼前的结果对不上时，以眼前的结果为准。

**选型口诀**：人脸多视图、构图转真人、穿衣合成用 GPT Image｜在已有图上编辑用 Nano Banana Pro｜写实光影与游戏二次元用 Seedream 5.0 Pro｜视频用 Wan 3.0

## 怎么用

1. 先问清用户当下能用哪些模型和通道（账号、额度、API、反代还是网页版）。
2. 按要做的内容在"选型"里找模型。最擅长的用不了，就选次优的，并说明会差在哪里。
3. 读这个模型的卡片，按它的特点写提示词。

## 选型

| 要做的东西 | 用这个 | 理由 |
|---|---|---|
| 正面基准脸、人脸锁定图 / 多视图 | GPT Image | 身份还原度最高，脸部清晰 |
| 在已有图上编辑（换发型、去妆、局部修改） | Nano Banana Pro | 编辑和多图融合能力强 |
| 写实人像 / 光影质感 | Seedream 5.0 Pro | 光影最真实，中日韩系更贴 |
| 游戏二次元立绘 | Seedream 5.0 Pro | 笔触接近主流游戏立绘 |
| 二次元构图转真人 | GPT Image | 转真人效果最稳 |
| 海报 / 场景还原 | GPT Image | 场景真实，首图就能用 |
| 视频用的写实空镜（不带人） | Seedream（即梦） | 比 GPT Image 真实得多 |
| 把人物合进已定的空镜 | Nano Banana Pro | 多图融合；抽两张，挑没重画场景的那张 |
| 穿衣合成（脸 + 服装） | GPT Image（ChatGPT 网页版） | 合成自然，头身比例正确 |
| 图生视频 / 参考视频复刻 | Wan 3.0 | 真人感最好 |
| 静态图放大到 4K/8K | `image-upscale` | 非生成式，只放大不重绘，脸不变 |

## 生图模型

### Nano Banana Pro

- **强在**：图像编辑；多图参考融合。
- **注意**：从参考图直接生成人脸多视图时随机性很大，同一段提示词两次生成可能不是同一个人。用它出锁定图要多抽几次比对，或者改用 GPT Image。
- **适合环节**：在已经认可的图上做编辑，比如换发型、去妆、改局部；把人物或道具合进已定的空镜；分格修皮肤。
- **把人合进空镜**：提示词写死人物的位置和大小。即便这样，两张里常有一张把整个场景重画（柱子、道具都换掉），要对照空镜检查。用三维白模当姿态参考会带进 CG 感、推近镜头，改用骨架图，见 `nuwa-motion`。
- **多格图改质感**：整张送去会重排版面，按格裁开分别修再拼回，见 `nuwa-polish`。
- **APIMart 通道**：`POST https://api.apimart.ai/v1/images/generations`，model `gemini-3-pro-image-preview`，`size` 用比例（auto、1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9），`resolution` 选 1K/2K/4K，参考图用 `image_urls` 传 Data URI，最多 14 张。异步：查 `GET /v1/tasks/{task_id}`，图片在 `data.result.images[0].url[0]`，链接 24 小时过期。4K 一张约扣 0.03、2K 约 0.02。参考图超过约 4MB 先转 JPEG，否则请求会被断开；下载经常中途断，按任务号续传，不要重新提交。

### Nano Banana 2.1（`gemini-nano-banana-2.1`）

- **强在**：多图参考融合。
- **注意**：一致性逊于 Pro。能用 Pro 时用 Pro。

### Gemini 3 Pro Image（`gemini-3-pro-image`）

- **强在**：骨相、肤质细节。
- **注意**：中面部结构容易偏。

### Seedream 5.0 Pro

- **强在**：光影真实；二次元笔触像游戏立绘。
- **注意**：真人偏大众脸、网红脸，记忆点弱。要求素颜时容易处理成"伪素颜"，仍然带妆。用来定一个要长期出镜的模特时要谨慎。
- **概念写真最还原**：同一条按字段写的写真提示词，它的美学、人物姿态和人物与环境的关系最接近参考图，复刻视觉首选。Seedream 5.5 编辑改图更强，适合在它的成图上做局部修改。
- **空镜很强**：写实场景空镜（停车场、客厅）明显比 GPT Image 真实，GPT Image 出的空镜地面常像雨后湿地、脏乱过头。视频要用的场景底图首选它（即梦）。

### Nano Banana 2 Lite

- **注意**：清晰度和真人感一般，不用来出锁定图。

### GPT Image（原生 image_gen / ChatGPT 网页版）

- **强在**：从外部参考直接生成人脸多视图，身份还原度最高、脸部清晰；场景真实；首图惊艳；能把构图转成真人；穿衣合成自然。多视图不画分割线时，接缝处理最干净。
- **注意**：
  - 在它自己的同一张成图上反复修改，面部会被一轮轮重绘，越改越不像本人。改图回到原始参考和已确认的定稿重出，局部修改换 Nano Banana Pro。
  - 参考图里没有对应角度的视角（比如严格的正侧面）容易崩，要单独检查。
  - 实际输出尺寸不受请求控制，约 1.2–1.6MP；多格图的分格是等宽的，布局可信，像素要按实际读。
  - 参考图总体积大时可能上游断连（`EOF`）：出现过 7 张约 2.7MB 失败、去掉最大一张后成功，是张数还是体积导致的还没分开验证。先压缩大图再减张数。
  - 写真类画面容易自行性感化：把短裤画短、让腿和臀部占据画面。细节最多，但注意力会从主反差跑到身体上；用它时在服装和构图字段写死长度、遮挡和人物大小。
  - 不写服装时，它会自己补一件上衣；要不露衣服就明确写出来。
- **写法**：
  - 有参考图时不写面部描述，人脸交给参考图；构图、背景、光线、服装、表情要写清楚。不写背景时它会自己选，出过纯黑背景。
  - 同一个人的参考图传得越多，人脸还原越准。
  - 要干净，不要"细节感"。写细节、颗粒、微阴影、真实纹理这类词，容易出噪点、脏灰调和过度锐化。下面"写实人脸"那张表里的纹理写法不要用在 GPT Image 上。
  - 噪点偏高、偏糊；多轮修改会过拟合。
  - 没有 seed；分辨率上限、局部重绘未暴露。
  - 走 CPA 反代时审核极严，常规服装都可能被拦。服装类走 ChatGPT 网页版。
- **回喂规则**：用户的原始参考图第一次出图首选它；尽量少把它的成图再喂给它。定稿往下一环传一次可以，不在同一张成图上反复改，局部编辑交给 Nano Banana Pro。详见 [参考分工](reference-roles.md) 的"选模型与成图回喂"。

### 写实人脸：有效和翻车的写法

适用于 Nano Banana 等会自己收敛到干净画面的模型。GPT Image 不适用，见它的卡片。

| 这样写有效 | 结果 |
|---|---|
| `soft directional window daylight` | 有明暗过渡 |
| `visible fine pores with micro-shadowing` | 毛孔可见 |
| `fine vellus hair catching the light` | 绒毛可见 |
| `natural lip texture with fine vertical lines` | 唇纹自然 |

| 这样写会翻车 | 后果 |
|---|---|
| `keep shadow density low` | 皮肤细节被磨掉 |
| `soft even diffuse frontal light` | 细节消失 |
| `no bright specular hotspots` | 表面质感削弱 |
| 冷白加多条去黄要求叠加 | 发白、发灰 |

### 生图其他要点

- **定妆四宫格**：正面头肩｜严格侧面头肩｜无头正面服装｜完整背面全身。上排约占 1/3 高，实际比例必须测量；格子越多，每格人脸的像素越少。
- **妆容转文字**：腮红写位置、浓度、边缘；唇釉写透明色膜；高光写分布。
- **验收七项**：身份、骨相、肤质、视线、手部、服装、多视角。

## 生视频模型

### Wan 3.0（`wan3.0-video`）

- **强在**：真人感最好；单条成片不剪辑直接发，真实感最强。
- **注意**：
  - **复刻时参考图的视角要对上参考视频。** 图片的视角、构图、机位和参考视频对不上，人物会畸变。
  - **会把参考视频里人物的外观带进成品**（手套、配饰、服装）。复刻前要列外观差异清单逐项排除，见 `nuwa-motion` 的防外观迁移。
  - **头和身体分开传时，头身比可能不符。** 脸部特写加无头身体图可以用，身份能保住，但可能偏大头。
  - 复杂运镜可控性未知，默认用固定机位。
- **参考怎么给**：
  - 首选合成好的全身图（脸、服装、比例都在一张图里）。
  - 做复刻时，挑和参考视频开头视角、机位最接近的那张；三视图里只有一格对得上，就裁出那一格单独用。
  - 要保持构图用 `first_frame`；用 `reference_image` 时构图和背景会变，要重新检查。
  - `first_frame` 只能和 `last_frame` 一起传，不能和 `reference_image`、`reference_video` 同时用；要带锁脸图或参考视频，就只能用参考生视频，把首帧也当参考图传。
  - **参考生视频时，人物的大小和位置跟着参考视频走，不跟参考图。** 要和上一镜衔接，先把参考视频里的人物缩放、平移到上一镜尾帧的站位，见 `nuwa-motion` 的「多镜头衔接」。这样做后，背景和人物站位都能锁得很好。
  - `ratio` 只有 21:9、16:9、4:3、1:1、3:4、9:16、adaptive，没有 2:3；空镜是 2:3 时按目标取景裁成 9:16 再用。
  - 480P 下全身的脸只有几十像素、偏糊，只用来试动作；正片用 720P。
- **提交参数**：

```json
{
  "model": "wan3.0-video",
  "parameters": {
    "resolution": "720P",
    "ratio": "3:4",
    "duration": 8,
    "audio": true,
    "prompt_extend": false,
    "watermark": false
  }
}
```

  - `prompt_extend` 保持 `false`：打开后模型会自动扩写提示词，可能把排除掉的东西又加回来。
  - 用 720P。480P 下全身构图的脸太小，容易崩。720P 档位 3:4 的实际输出是 832×1108。
  - 通道、主机、密钥变量以项目配置为准。
- **写法**：
  - 固定机位、正常速度、单镜头，每段只安排少量动作。
  - 手要写成过程：抬起 → 转腕 → 接触衣料 → 松开 → 回落。只写"双手自然垂下"，手会停住不动。
  - 身体、头发、衣料按重量和惯性写，见 `nuwa-motion` 的物理动态写法。
- **必查**：手指、手腕、衣料穿模、配饰数量、背景漂移、包带随动、画面边缘入画。

### Seedance 2.0 Mini

- **注意**：输出 720×960，不支持 1080p。全身构图时脸只有约 70 像素高，换姿势时五官逐帧漂移，整体偏糊。远景人脸会糊。
- **结论**：不用来做全身真人视频。

## 非生成工具

### image-upscale

- **强在**：非生成式超分（DAT2、HAT），只放大不重绘，脸和细节不变。
- **注意**：不会增加原图里没有的细节。
- **用在**：成品图放大到 2K、4K、8K。
