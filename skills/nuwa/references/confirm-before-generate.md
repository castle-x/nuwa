# 生成前确认

默认状态下，**真正调用生图或生视频接口之前，先出确认单，拿到用户的确认再提交。** 这是流程的一部分，不是礼貌动作。用户自己在网页端生成时，不需要确认单，但提示词、参考图清单和来源仍要交代清楚。

## 什么时候可以跳过

只有一种情况：用户在本次任务里明确说了不用确认，比如"直接生成""不用问我""自动化跑完就行""按这个方案全出"。

不能当作授权的：之前某一次说过"直接生成"、上次同类任务没确认、你已经解释过方案、用户说"可以""看着办""你觉得好就行"、"时间紧"。授权只对本次有效；换批次、换角色、换模型，都要重新确认。判断不了就确认。

## 确认单里必须有的四块

1. **生成参数**：通道、模型标识、画幅与分辨率、张数、预计花费、输出目录、批次名。张数标明来源：用户指定 N 张，或默认 1 张；用户没要求就不能自己调高。同时列出已确认的选择：发型、妆容、服装与配饰各自保留还是调整；皮肤高光保留还是减弱；表情是默认的中性表情还是用户指定。
2. **提示词原文**：完整文本，含负面约束，一字不改，不写"同上"，能直接复制。原文不是中文时附中文对照。
3. **参考图清单**：每张图的缩略图、文件名、尺寸、职责、来源（用户原始参考，还是哪一次生成的成图）。
4. **自检**：每张图来源已标注；成图回喂已说明；比例来源唯一；顺序与职责已写清。

## 怎么生成

用脚本渲染，不要每次现写一份 HTML，结构一变，用户就得重新找按钮：

```bash
python3 <nuwa>/scripts/confirm_sheet.py --示例 > 任务.json   # 打印任务模板，按本次任务填写
python3 <nuwa>/scripts/confirm_sheet.py 任务.json --open     # 渲染并打开
```

在项目根目录运行，参考图路径相对项目根目录。输出默认在当前目录的 `确认单/`，建议用 `--out` 指到这次任务的生成记录目录（见 [制作档案](archive.md)），项目有自己的目录约定时以项目为准。确认单是自包含的单文件 HTML，参考图压缩后内嵌，离线、换电脑都能完整打开，手机上也能看。需要 Pillow。

## 交到用户手里

在会话里给出确认单的可点击链接，用户点开就能看。不要只写一个裸路径，不要用截图或会话组件仿制一份确认单（两份会各说一套数字），不要为了让人点开去起外网链接。

## 回执

按可用性从高到低：

1. **下载回执**（默认）：用户点"确认生成"，下载 `回执-<jobId>.json`。提交前读这个文件，核对 `jobId` 和提示词指纹与当前任务一致。
2. **口头确认**：用户回一句"已确认 <jobId>"，把原话和 jobId 记进生成记录。

`jobId` 不一致是确认了旧单；提示词指纹不一致是提示词改过；回执时间早于最后一次修改则作废。这三种都不放行，重新出单。

## 确认之后

只提交确认单上完全一致的内容，改一个字都要重新出单。一批出完，把 jobId 和回执写进生成记录。用户中途改需求，旧单作废。一单一角色一任务，不要一次出几个角色的单子。
